# 16对象活动状态数据冻结与PrimGLR十例图审

用户授权日期2026-10-17。引用docs/public_appliance_comparison_cohort_9plus7.md v4。
活动状态是主项目提取步骤输出的有上下文支持片段，不要求整次设备程序。

输入16对象的真实时间戳及有功功率；保留设备更换分界、缺测与原生时间。
按configs/plan.json的逐对象阈值、t_drop、t_min_work提取，所有片段实际调用主项目ExtractActiveDataStep.simple产生；固定resample_fs=0，context_by_time=true。
针对子秒数据修正主步骤边界整数截断，新增按真实时间取上下文选项，默认点数上下文路径保留；先执行合成契约验证。
先用相同simple检测规则枚举候选，再对入选上下文窗实际调用主步骤；校验选中主步骤CSV时间/功率、核心索引与候选逐点相同。连续有效支撑先分块，不填补缺测。
REFIT检测输入沿用8秒epoch对齐、最大16秒ZOH支撑、coverage>=.8；原始序列副本仍保存原生点。

咖啡机请求[2020-03-21,2020-12-03)，冰箱请求[2025-07-20,2025-09-05)。若主步骤计数变化超过599，依预声明规则将起点向后调整至最早满足上限的整日，报告调整前后数量和日期；不随机删样。其他14对象保留源历史和元数据设备时期，分时间块后在各划分日期层内确定性选样至原上限，不按切分分数选样。
同日及上下文重叠片段同组，按时间顺序约60/20/20划分；样本不足或空划分如实报告。图审选验证侧十例，不足则补开发侧，禁止使用测试侧选参。
PrimGLR固定W=120秒、gap=30秒、alpha=.9、dur_sigma=.35、g_wf=16、g_env=8、n_clusters=null；按实际来源nominal换算点数。每对象一张5x2十例图，显示核心、上下文、日期、切点和真实耗时，缺例留空。图审pending，不自动冻结为论文最终参数。

CPU执行，不使用GPU或Slurm；按四个数据集队列并行，每队列内逐对象处理，每进程2线程，监控内存和I/O。每阶段经create_execution.py/run_execution.py登记，历史执行不覆盖。
两组独立物理文件复制到datasets/public16_activity_states_20261017/<object>/source/与activities/，不用指向runs的软链或硬链。source为选定连续区间的原始序列；activities为主步骤CSV及对应带索引NPZ。活动上限选样由activities.json逐条标识，原始区间可含未入选活动。
验证输入来源、时间严格递增、数据支撑、核心包含、主步骤实际输出、相等数组、原始时间区间映射、独立复制文件哈希一致以及全部16对象路径存在。各对象保存源区间、候选和剔除理由、划分、SHA256、图审ID；主报告汇总两组真实路径。
本实验不进行聚类、生成训练或人工边界F1。
