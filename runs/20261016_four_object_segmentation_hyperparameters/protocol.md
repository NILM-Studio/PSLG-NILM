# 执行协议

状态：已授权第一阶段。正式实验一尚未授权启动。

1. 注册 `prepare`，只读核对旧复核四对象的活动清单和逐条 `.npz` 哈希；按活动核心时间与重叠上下文构成时间块，以连续块划分开发/验证/评价，目标比例 60/20/20，保存精确 ID 与比例。旧全量调参暴露记录写进报告。
2. 注册 `pilot`，每对象各取一条短、一条中等和一条较长的开发活动，分别试运行六方法的默认或中位候选；记录 CUDA 卡占用、单活动耗时、模型错误和可用长度。pilot 不选择赢家。高代价方法按此测算筛参预算；不可偷偷减少某方法的失败样本。
3. 冻结筛参活动（开发侧按时间、时长、截断分层）和验证活动。所有候选在相同对象活动上评估；资源不足时采用统一逐级筛选，明确每阶段样本数和预定晋级数。PrimGLR 可复用哈希完全相同的旧中间量，但旧全量建议不直接胜出。
4. 第一阶段硬检查：切点严格位于活动内部、升序无重复、全点覆盖，失败与不适用单列。验证汇总含完整活动与核心、全部与未截断、实际秒数、活动覆盖、切点数、短段、时间加权 NRMSE 和运行时。旧代理绝对 85% 门槛不作为本实验硬门槛；与基线的差异和适用性完整报告。
5. 候选审核：先排除结构失败或明显覆盖损失，再提供边界密度/无切点率、短段、NRMSE、代理及十子图给用户审核。CSR_SE 定义与共享参考尚需按源码恢复；若本阶段未完成，则不以其选参。任何权衡与未达标均透明记录，不能自动声称 H20 已解决。
6. 每对象×方法最终只冻结一组参数，**须先取得用户对十子图的人工审核结果**。Clasp 先经人工审核并冻结，CLaP 再继承该初始边界。保存真实点数、自动窗口、随机种子、包版本、输入及代码哈希。E2USD 选择 GPU 空闲卡，Numba CUDA 禁用仅限 STUMPY CPU 路径，不影响 Torch。
7. 每次运行使用注册执行目录、代码快照与退出码；失败后新建执行，不覆写。人工审核前只出候选汇总、审核图、`hyperparameters.md` 草稿和待审核清单，不出最终 `configs/frozen.json`；人工审核后才写冻结配置并追加最终实验日志。第二阶段另登记，不在本实验内运行。

## 筛选规则（在正式筛参前冻结）

- 每对象从开发侧选 12 条、验证侧最多 12 条活动。按核心起始时间四分位 × 样本长度三分位取每格中位活动，不足时按时间顺序补齐。短活动、零切点和不适用均保留。四对象各方法共享同一组 ID。
- PrimGLR 首轮固定 `dur_sigma=0.35`；首轮 48 个组合，H20 为 80 个。每方法每对象按候选在同一开发集上的**成功活动数降序**筛选，再按下式得分升序，取前三名，并强制补入该方法的当前默认配置（若它不在前三名）。结构异常或真正运行错误不能进入决赛。
- 得分只用于**同对象同方法**的配置排序：`mean(core_nrmse) + 0.01 × mean(core_cut_density_per10min) + 0.02 × mean(core_short30_fraction) + 0.02 × (1 - sum(proxy_matched)/sum(proxy_total)) + 0.02 × mean(zero_internal_cut)`。所有均在成功活动上计算；代理跃迁只作弱证据，绝不等同真实边界。成功数优先于得分；不适用条目公开列出。
- 决赛在冻结的验证活动上运行。PrimGLR 对晋级的每个 `(W,min_gap,alpha)` 追加 `dur_sigma=0.2,0.6`，其余方法按原候选；E2USD 的每个决赛配置运行种子 0、1、2，其余保持实现固定随机种子。按成功活动数、上述得分、总运行时、参数字典序逐级排序，仅形成**机器建议**，不能自动冻结。Clasp 人工审核后 CLaP 才进行正式筛参；先行使用机器建议的 CLaP 结果只能标为探索性，不构成冻结配置。
- 评价侧在第一阶段保持封存，不参与排序。这个分数是无人工真值条件下的预先声明的工程折中，并不估计真正的切分准确率。报告分别展示其五个分量，保留真实活动波形供人工检查；图审可标记失败，但不得无记录地替换赢家。
- 第一阶段沿用既有 `20261016_public_activity_segmentation_recalibration` 的十子图语义：**每张图固定同一条活动波形，5×2 十格比较至多十组候选参数**；同对象各图保持坐标范围，黑线功率、灰色上下文、红色虚线切点，活动核心边界和截断状态可见。每对象选十条固定开发活动，每对象×方法最多十张图；候选不足十组的格子明确写“无更多候选”，不复制候选凑数。PNG/SVG 双格式，逐子图清单保存输入哈希、参数、切点索引/真实时间与绘制线数。验证侧入围候选另附同结构检查图，供用户最终审查。此前设计的“十条活动各占一个子图”不符合本项要求，废止。
- 2026-10-16 用户进一步明确：第一阶段参数必须通过上述十子图由人审核。此前 PrimGLR、FLUSS 两组自动 `freeze_*` 执行仅作为算法排名历史记录，产出的 `selected_*.json` 已移至 `data/provisional_auto_before_human_gate/`，**均未获人工批准**。自动冻结协调脚本已停止；后续 `freeze.py` 必须读取有审核记录的决策文件才可运行。
- 为让用户同轮看到六方法，CLaP 可先用经验证指标推得的**暂定 Clasp 初始化**制作探索性十子图，输入文件及哈希显式记录。此结果不能视为正式 CLaP 筛参或冻结；若人工选择了另一组 Clasp 参数，必须重跑 CLaP 并重新出图再审核。
- E2USD 的验证十子图把入围参数与随机种子 0/1/2 分开标注，十格最多展示十个“参数×种子”结果；用户可以直接观察同一参数的切点稳定性，统计表仍按预定三种子汇总。
