# Amendment 1: FLUSS threshold search

记录时间：2026-10-16。首次 FLUSS 开发筛参与验证完成后登记，属于**事后修订**。

原网格为 `window_seconds=[60,120,180]` × `threshold=[0.35,0.45,0.55]`。首次验证 H7 和 H20 的胜出配置在全部验证活动上均为零切点；两者的代理跃迁漏检率均为 1.0，无法提供有意义的切分对照。扩大阈值为 `[0.35,0.45,0.55,0.65,0.75,0.85,0.95]`，窗口网格及算法实现不变。新配置位于 `configs/search_space_amendment1.json`。

旧执行及其 `data/finalists_fluss_threshold.json`、`data/selected_fluss_threshold.json` 结果归档保留。新一轮只重跑 FLUSS 四对象的开发侧候选及相同验证侧候选，所有执行另行注册。因为已观察首次验证结果，第二轮验证侧的模型选择属于探索性确认，不再声称盲态独立验证；正式实验一只能在冻结后使用封存评价侧做最终比较，且不得再凭评价结果调参。

阈值扩展的目标是检验适当的 CAC 最小值是否能产生非空切分；不保证该方法会胜出，也不把代理跃迁当作真实边界。
