# 真实基元组合实验：2026-09-17 服务器交接

> 本文保留 `af7dbd2` 四组交接基准。当前入口已扩展为五组，并新增分层指标和波形报告；最新运行目录与命令见 [Unit Selection 第一阶段](primitive_unit_selection_20260917.md)。

## 目标与贡献边界

师兄负责已有切分、特征和聚类基础，师弟后续提供基元波形生成模型。本轮先用真实状态基元研究组合策略，不修改上游算法，不训练 diffusion，不以模型比较替代本人的组合方法研究。

本轮问题：固定状态顺序、时长和候选波形，只改变候选选择方式，能否得到更合理的完整周期？这是研究原型和工程验证，不是已证明的新方法或论文结论。

## 四组严格配对的比较

| 方法名 | 选择规则 | 作用 |
|---|---|---|
| `random` | 从共享候选池随机选 | 最低组合基线 |
| `boundary_greedy` | 逐步选择与前一块端点最接近的候选 | 复用现有端点匹配思路的受控基线 |
| `boundary_dp` | 固定首块，动态规划最小化全部接缝的端点差异成本 | 单独检查全局搜索的影响 |
| `transition_dp` | 固定首块，用真实相邻状态拟合的兼容性成本进行动态规划 | 本轮兼容性原型 |

四组共享：锚点、状态序列、每块目标时长、每个位置的完整候选池、首块候选、插值策略和种子。全部关闭接缝平滑；电器合法状态转换允许有功率阶跃，不能把跳变越小当成物理质量越好。

这里的边界基线与旧 `RealPrimitiveSampler` 使用相同端点匹配思想，但不是旧生成器的逐字节复现。为了只比较选择机制，本轮先将完整候选状态块适配到固定长度，不再让各方法在生成过程中各自抽取不同数量的小片段。DP的边成本为 `log(1 + abs(jump))`；贪心排序与原始绝对差一致，DP优化的是变换后的总成本。

### 候选块和来源

- 单位是继承目录中的连续同状态块，可由多个原始切割基元构成；保存其原始 `primitive_ids`、源周期、源位置和源长度，不重新切分/聚类。
- 候选仅来自当前预算内同 Class/Mode 的其他训练周期，明确排除锚点。
- 对源块做线性长度适配，默认目标/源时长比例限制在 `[0.5, 2]`。这是四组方法共同的预处理，不是神经生成，也不保证所有快慢变化都物理合理。
- 候选池每个位置默认最多8个，不够8个时不重复补齐。
- 单例组、缺少同状态且时长合格的供体、少于两个状态块的锚点，对全部方法共同跳过。保留原因和数量，不用锚点自身回填。

### 兼容性模型到底是什么

这是一个轻量、可检查的经验参考模型，不是训练好的判别神经网络，更不是新的基元生成器。

每个锚点仅使用同预算、同Class/Mode、非锚点周期的真实相邻状态对，按 `(左状态, 右状态)` 建立参考库。描述量包括两块平均功率与波动、带符号的接缝功率变化、左右局部变化率和时长比。对数变换后用训练参考的中位数/IQR缩放，再计算平均最近邻距离。模型清单记录实际拟合周期ID、支持量、缩放参数及特征定义。

默认某状态转移至少需要3个独立供体周期；同一个周期出现很多次不算多个独立支持。支持不足的边明确退回边界成本，并记录 `transition_fallback_edges`。若全部边都回退，`transition_dp` 等价于 `boundary_dp`，不能当成兼容性学习成功。

部分回退时，路径成本混合经验距离与对数端点差，两者尚未校准为同一尺度。因此本轮保留回退作诊断，不能把混合支持案例与全支持案例不加区分地汇总为方法有效性结论。

## 服务器：一条命令启动第一轮

在服务器允许的CPU计算环境中，激活项目已有Python环境。不要 `source slurm/env.sh`：旧脚本会强制检查GPU，而本实验不需要GPU。

```bash
cd /home/scnu2024024563/NILM/PSLG-NILM
git switch feature/primitive-generation
git pull --ff-only origin feature/primitive-generation
conda activate pslg-nilm
bash scripts/run_composition_validation.sh
```

默认输入已有 `ukdale_wm_primglr_detsec_3789`；默认新建 `ukdale_wm_composition_20260917`。脚本依次：

1. 创建新的下游实验清单，只引用旧上游文件，不复制数据、不覆盖旧实验。
2. 检查继承原语覆盖、状态位置、信号有效性和换机时期分布。
3. 在新目录运行 `temporal_holdout,cycle_classify,cycle_validate,cycle_split`，不运行切分、特征、聚类或状态合并。
4. 在 5%、10%、20%、100% 的训练周期预算下，以 seed42、每预算至多30个锚点完成四组对照。
5. 独立读回 NPZ，核验文件哈希、候选一致性、时间/状态模板和来源范围。

旧产物缺失、接口不完整、剔除后空划分等情况会停止并留下日志，不跳过。第一次失败后直接发错误和报告，不反复启动训练。

如源run名称不同，或需要保留一次失败实验再重跑，可明确使用新名称：

```bash
SOURCE_RUN_ID=你的已有上游run \
RUN_ID=ukdale_wm_composition_20260917_r2 \
bash scripts/run_composition_validation.sh
```

目标run已存在会拒绝，不覆盖其报告/时间划分。可通过 `PYTHON_BIN` 指定当前环境Python绝对路径；`RATIOS`、`SEEDS`、`MAX_ANCHORS`、`CANDIDATES` 可覆盖默认值。

本轮不需要新的有功总表对齐文件，因为这里只生成电器支路波形。输出NPZ没有 `mains`，不能直接送入现有Seq2Point训练器。该原型尚未替换 `nilm_dataset` 的 C 组，也尚未接入师弟的生成模型。待拼接报告确认后，再接入物理可加总的背景与下游训练链。

## 怎样理解结果，避免假进展

- `audit.passed=true` 只证明实现层面的配对、来源与文件一致性，不证明波形物理正确。
- `boundary_dp` 比贪心边界成本低，或 `transition_dp` 比其他方法兼容性成本低，是优化的预期结果，不是独立科学证据。
- 查看 `cases_with_supported_transitions` 与各例回退边数量。若没有支持，本轮并未真正检验经验兼容性。
- 查看 `single_donor_cycle` 和 `nearest_donor_resampled_nrmse`。多个状态全部来自同一个供体、或非常接近某个供体完整周期，可能只是换一个真实周期重放；不能宣称获得新颖生成。
- 验证集只用于生成结束后的描述统计：按Class/Mode给出能量、平均/峰值功率和接缝变化分布。验证样本少或没有匹配组会明确报告。汇总接缝分布混合不同转移类型，不能单独当成有效性判据。
- 测试波形只在上游完整性审计中被读取；不参与候选、拟合、选择或本轮性能评估。不要用测试集决定这几种组合方法的超参数。
- 预算分母是经过周期验证的训练目录周期数，尚未经过总表对齐，因此不等同旧NILM数据集的预算分母。各预算嵌套；30锚点上限是诊断采样，不是全量实验。
- Class/Mode是经验标签，不是真实洗衣程序。继承表示与类别资源的完整拟合范围仍未认证，不能声称端到端无泄漏。来源若跨两台机器，本轮首先是协议诊断，不能直接作为同机主实验。

收到第一轮报告后，先判断覆盖是否足够、是否大量回退/重放、真实验证分布是否异常，再决定哪些组进入多种子和NILM实验，不预设哪种方法一定更好。
